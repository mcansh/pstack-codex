### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.codex/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, PR state, and unknown agent liveness, then suggests a bucket. It never scans private session history. `verify-liveness` is not safe-to-delete evidence.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-liveness` row or other uncertainty, use an available agent-status tool or ask the user whether the worktree and any sibling delegate checkouts are active. Read only explicitly supplied in-scope history, never discover private chats by scanning directories. Transcript timestamps do not prove liveness. If usage cannot be established, hold the worktree.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first. `scratch:N` means untracked files, not disposable files. Inspect them and obtain authorization before deleting them. Even a clean, merged, unused tree needs the user's deletion grant. Preserve unrelated work and hold anything active or uncertain.
5. Prune the confirmed set. Per authorized path, use `git worktree remove <path>`. If Git refuses, inspect the remaining files and report the blocker; do not force deletion. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Inspect simulator clones and old runtimes with available platform tools. Inspect Xcode build artifacts and package caches only within the requested scope. Name exact targets, verify they are unused, and obtain deletion authorization before clearing them. Do not remove application databases, snapshots, or private conversation state as a generic cache cleanup.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
